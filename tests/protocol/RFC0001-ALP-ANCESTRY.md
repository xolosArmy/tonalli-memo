Status of this file: isolated S0 evidence on PR #41. It is not a production
change, not a ratified tip profile, and not a mainnet genealogy of RMZ.

RFC-0001 remains PROPOSED — NOT RATIFIED. SEC-17 remains design approved,
productive mitigation pending. S0: OPEN. S1: NOT AUTHORIZED. Social version
`0x02` stays inactive. M1.7.4 remains open.

The oracle is `tests/protocol/alp-ancestry-independent.mjs`. The chain is
`tests/fixtures/rfc0001-alp-ancestry.json`, regenerated by
`tests/protocol/generate-alp-ancestry-fixtures.mjs`. Replay and synthetic

and the BIP143/ForkID authorship check are independent of that builder. No
node is contacted and no transaction is broadcast.

## Laboratory results

The synthetic token ticker is `LAB`. Its token id is the TXID of
`lab-genesis`:

`79dee0245d45dc842e82aa37f639c325b8c62cc5d151fc7778a33f5e1c20e251`

That id is not the public RMZ id. Genesis metadata records decimals `2` and
creates one mint baton. Mint authority in this laboratory is the live baton
output, not the optional `auth_pubkey` field, which is empty. `lab-mint`
spends that baton and issues `7000` new atoms. `lab-send` spends the
`10000`-atom genesis output and maps `125` atoms to output 1 and `9875`
atoms to output 2. The sums match. `lab-mint-send` spends the minted atoms.
A second genesis, ticker `FOR`, is a different token id. A third genesis,
ticker `DEC`, records decimals `0`.

Two locally consistent tip transactions, author input 0 and author input 1,
attribute `125` laboratory atoms to the other key. Their receipt state is
`PENDING`. A third positive control, `lab-author-owns-tokens-foreign-xec`,
keeps that result when author B adds an XEC fee input and author A, designated
at input 1, still owns the only LAB prevout. Confirmation and settlement are
`NOT_DEMONSTRATED`. The synthetic target TXID is not a verified post.
`socialEventCredited` stays false. `realRmzTip` stays false. The laboratory
transfer label is `LABORATORY_ATTRIBUTED`, which is not a settled payment.

The designated author HASH160 must own every fungible input of the token
being transferred. An XEC input from another sponsor is not token ownership.
A valid signature by A does not attribute B's atoms to A. Foreign or
ambiguous funding stays `AMBIGUOUS_TIP_FUNDING` and credits `0`. That label
is experimental. It is not a new public receipt code.

`lab-sponsor-signs-foreign-tokens` was evaluated on the previous oracle.

## Historical prevout binding

The previous laboratory oracle, at
`7308a3d51b5e607825ec05720611db0c79e5c19e`, rebuilt each BIP143/ForkID
preimage from `record.inputs`. Those fields are copied from the signing
spec. The UTXO map stored the token id, atoms, baton and owner, but not the
satoshis or the locking script. Parent bytes were already present as
`rawTransactionHex` and were not consulted. The following rows were measured
on an isolated document of `lab-genesis` plus one attack, before any oracle
change. A digest match against declared metadata is not, by itself, the
chain result.

The amount row is the false attribution. The script and wrong-index rows
were applied even though the signing key did not control the historical
P2PKH. The sibling row burned a fresh output that the missing index never
unlocked. Those six results are the counterexamples. They were recorded
before the oracle was changed.

The correction is only in `evaluateChain` and `attributeTip`. For an
outpoint whose parent TXID has been retained, the oracle parses that
parent's stored bytes, checks the TXID, requires the output index, and reads
the satoshis and locking script from that output. The prevout correction
retained a parent only when the transaction was applied. A consensus-valid
ALP rejection still burned its inputs and left its outputs out of the chain.
The replay section extends retention and records that gap. The preimage, the sighash
and the HASH160 are checked against those bytes. `record.inputs` can show a
disagreement. It is not the source of a historical output. A script
disagreement is `PREVOUT_SCRIPT_MISMATCH`. An amount disagreement is
`PREVOUT_AMOUNT_MISMATCH`. Both are reported together when both differ. An
index past the parent is `PREVOUT_INDEX_MISMATCH`. An `externalUncolored`
flag on a chain outpoint is `EXTERNAL_CLAIM_CONTRADICTS_CHAIN`. Each of
these is consensus-invalid. The transaction is not applied, creates no
colored outputs, and cannot be `LABORATORY_ATTRIBUTED`.

`classifyAuthor` and `inputUnlockMatchesPrevout` are unchanged. The ancestry
oracle passes the historical prevout into them. A chain input therefore
cannot make the author HASH160 follow a lied script. An explicit external
fee, whose parent is not in this chain, still uses its fixture prevout and
is labeled `EXTERNAL_NOT_DEMONSTRATED`. That label is not a mainnet check
and not a trusted-chronik check. An unmarked prevout whose parent is absent
stays `PREVOUT_NOT_IN_CHAIN`, now consensus-invalid, and does not burn a
sibling. A consensus-valid transaction with an invalid ALP section still
burns known inputs. `lab-malformed-action` and `lab-duplicate-section` keep
consensus `VALID`.

The same isolated attacks, evaluated again after the correction, are
consensus-invalid and not applied. The amount attack is `INVALID_AUTHOR`
with attributable `0`, not `LABORATORY_ATTRIBUTED`. The isolated wrong-index
attack declared 10000 sats, so its only chain reason is
`PREVOUT_SCRIPT_MISMATCH`. The false external claim is
`EXTERNAL_CLAIM_CONTRADICTS_CHAIN` and `INVALID_ASSET`. The missing index is
`PREVOUT_INDEX_MISMATCH`. The sibling's fresh output is only referenced. It
is not marked spent.

## Synthetic replay, rollback and reorg

The ancestry chain above is unchanged. Replay uses its own LAB genesis.
That token id is the TXID of `replay-genesis`:

`d83bc0e899c233e34fec614d5843cb3f20911fd8b450bf2bff48a99df88eac5a`

It is not the ancestry token id and it is not the public RMZ id. Genesis
issues `20000` fungible atoms and one baton. `replay-mint` spends the baton
and issues `1000` atoms. Laboratory supply is cumulative issuance, `21000`.
A later burn does not subtract from that counter and does not issue the
atoms again. Block indexes in the fixture are a local order. They are not a
network height, a confirmation, or finality.

Before any replay change, at `27a22416059cc5f6aa5cc4b11723186f23fe6b91`, an
isolated document showed the parent gap. A signature-valid SEND whose action
byte was `0xD3` spent a genesis output. The parent was consensus `VALID`,
applied false, reason `MALFORMED`, and it consumed the colored input. Its
raw bytes were not stored. A later honest spend of the carrier that parent
created was consensus `INVALID`, reason `PREVOUT_NOT_IN_CHAIN`, source
`UNAVAILABLE`. Authorship against the declared input stayed `LAB_VALID`.
The receipt was `INVALID_ASSET` with attributable `0`. The same spend with
`externalUncolored: true` was source `EXTERNAL_NOT_DEMONSTRATED`, consensus
`VALID`, applied false, reason `INFLATED`. That output was not
distinguishable from an external fee whose parent was never in the chain. An
honest spend of the genesis output itself stayed `LOCAL_CHAIN` and
`LABORATORY_VALID`. Those four results are the counterexample.

The cause was the success path. Parent bytes and UTXOs were written only
for `LABORATORY_VALID`. A consensus-valid ALP rejection burned known inputs
and dropped its outputs. The correction keeps the raw bytes and the outputs
of every consensus-valid transaction. Outputs of an ALP rejection are
uncolored: `tokenId` null and atoms `0`. They are not an issuance. A
consensus-invalid transaction is not retained, creates no UTXO, and cannot
be spent as `LOCAL_CHAIN`. The success path still writes colored outputs
once. `classifyAuthor` and `inputUnlockMatchesPrevout` are unchanged.

The same isolated spends, evaluated after the correction, resolve the
carrier as `LOCAL_CHAIN`. The honest child is consensus `VALID`, applied
false, reason `INFLATED`, and it consumes an uncolored input of atoms `0`.
The external claim is consensus `INVALID`, reason
`EXTERNAL_CLAIM_CONTRADICTS_CHAIN`, and it does not spend the output. Neither
is `LABORATORY_ATTRIBUTED`. The permanent chain locks that pair and the
negative case below.

The ancestor is genesis plus mint. Branch A spends genesis output 1 with a
conserving SEND of `125` atoms to the observer and then a hop of those `125`
atoms to author B. Both tips are `PENDING` / `LABORATORY_ATTRIBUTED`. The
attributable sum is `250`. Unspent colored atoms stay `21000`. Branch B
replaces that transfer. A malformed SEND burns output 1. An external claim
on the malformed carrier is `EXTERNAL_CLAIM_CONTRADICTS_CHAIN` and leaves
the carrier unspent. The following honest SEND is `INFLATED`, source
`LOCAL_CHAIN`, receipt `INVALID_ASSET`, authorship `LAB_VALID`, attributable
`0`. A flipped signature spends output 2 and does not consume it. A child
of that rejected transaction is `PREVOUT_NOT_IN_CHAIN` with source
`UNAVAILABLE`. Its authorship against the declared prevout stays `LAB_VALID`.
That child is the negative case: a consensus-invalid parent is still
indistinguishable from an absent prevout, and the oracle does not invent a
chain output for it. Output 3 is a different conserving SEND. Its tip,
`replay-tip-b`, is the only `LABORATORY_ATTRIBUTED` receipt on branch B, for
`125` atoms. Unspent colored atoms on B are `11000`. The `10000` atoms burned
by the malformed section are not credited to a tip and are not added to
branch A's `250`.

A checkpoint is a `structuredClone` of the laboratory state. Replaying
branch A from that ancestor matches a from-scratch replay of the same
records. Applying those txids again records one skip per transaction and
leaves the logical state, the supply, and the attributable sum unchanged.
Restoring the ancestor and applying branch B matches a from-scratch
reconstruction of B. The two branch A tips are then `NOT_ON_ACTIVE_CHAIN`
with attributable `0`. That status is not a public receipt code. Applying
branch B on top of branch A, without restoring the ancestor, does not match
B. The malformed spend is `ALREADY_SPENT` because output 1 is still consumed
by branch A.

No receipt in this replay reports confirmation, settlement, or reorg
finality. All three stay `NOT_DEMONSTRATED`. Withdrawing a tip does not
settle it. A synthetic branch switch is not a mainnet reorg and not indexer
finality. External fees remain `EXTERNAL_NOT_DEMONSTRATED`. M1.7.4 remains
open.
