## Framing

`TIP_XEC` is version `0x02`, event `0x05`. The envelope is 35 bytes:
version, event, author index, and a 32-byte display-order `target_txid`.
The script is 42 bytes: `OP_RETURN`, a minimal 4-byte LOKAD push, and
one minimal push of the envelope. Encoder A and encoder B produce the
same bytes. The published S-08 script is a format witness only.

A truncated envelope and a PUSHDATA1 envelope are rejected by the
laboratory decoder. Unknown version `0x09` and unknown event `0x7e`
are rejected. The unmodified Core parser returns `UNSUPPORTED_VERSION`
for every minimal social script in this corpus, because it rejects the
version before the event byte. The nonminimal script fails Core as
`INVALID_FORMAT`. The eligible target remains a Core v1.0 POST and
still parses.

`target_txid` is stored in display order. The decoder returns that hex.
It does not reverse the bytes and it does not treat them as UTF-8.
A 42-byte script is not evidence of a transfer.

## Authorship and funding

Positive rows cover Schnorr and ECDSA, sighash `0x41` and `0xc1`, and
author index 0, index 1, and index 2. The designated input may be any
in-range index. Input zero is not assumed to be the tipper.

M1.4.2 allows an extra fee-paying input for ordinary authorship.
M1.6.3 is stricter for this profile. Every funding prevout must be a
standard P2PKH controlled by the same HASH160 as the designated tipper.
A positive row with a nonzero index therefore uses several prevouts of
that same tipper. A fee input with a different hash is not credited.

Those prevouts are deterministic laboratory metadata from the canonical
fixture signer. They are not mainnet history and they are not Chronik
results.

The recipient HASH160 is the designated author of an eligible Core v1.0
POST. The eligible POST in this corpus uses author index 1. Its input
zero is a different hash and is not the recipient. A second eligible
POST carries 73 bytes of UTF-8 text (a 76-byte minimal `PUSHDATA1`
envelope) at author index 1 and is also accepted as a tip target. An
alias, a profile address, and input zero of the POST are not substitutes.

The laboratory amount is the positive integer sum of P2PKH outputs to
that recipient hash. OP_RETURN, the fee, change back to the tipper, and
outputs to any other hash are excluded. Two outputs of 1000 and 2000
satoshis credit 3000. RFC X-02 names 400 and 600 as logical amounts.
Those values sit below the 546-satoshi dust output used elsewhere in
this repository, so this laboratory uses relay-sized outputs instead.
One mixed row also pays 546 satoshis to a third hash and does not add
that output to the tip.

`LAB_ATTRIBUTABLE` means the synthetic checks passed. `settlement` and
`confirmation` stay `NOT_DEMONSTRATED`.
This laboratory is not a network settlement and not a productive indexer.

## Negatives

A recipient-funded counterexample follows the M1.6.3 amounts: the
tipper spends 1000 satoshis, the recipient spends 1000000, and the
outputs return 1000000 to the recipient and 500 to the tipper. The
output sum to the recipient is 1000000. The credited tip is 0, with
`AMBIGUOUS_TIP_FUNDING` and detail `RECIPIENT_INPUT`. The 500-satoshi
change is the specified counterexample. This note does not claim that
output is relay-valid.

A third-party input credits 0 even when the designated tipper's
signature checks, including sighash `0xc1` and a tipper who is not
input zero. Truncating the declared prevout metadata array so it covers
fewer entries than the serialized transaction inputs credits 0 as
`AMBIGUOUS_TIP_FUNDING` with detail `PREVOUT_UNAVAILABLE`. Flipping a
non-designated funding input signature or falsifying a non-designated
funding input amount credits 0 as `INVALID_FUNDING_SIGNATURE`. A tipper
whose hash equals the recipient is `SELF_TIP_UNCREDITED` even though
the transaction pays that hash.
A missing prevout, a prevout whose script or amount was replaced after
signing, an unsupported prevout script, a flipped signature, a mutated
recipient output, and a tip script mutated after signing credit 0.
An author index of 5 with one input credits 0. A zero-satoshi output
to the recipient is `NO_VALUE_TRANSFER`. A payment to the POST's input
zero, instead of the POST's designated author, is `INVALID_RECIPIENT`.

A missing target, a supplied target whose transaction ID does not match
the signed `target_txid` in the tip envelope, a payment, a reply-shaped
version `0x02` script, a POST whose own signature was altered, and a target
transaction containing more than one TM1 candidate output (`ineligible-duplicate-candidates`)
do not yield a credited tip (`TARGET_INELIGIBLE`, 0 satoshis).
The same target recorded on `lab-tip-net` does not satisfy a tip
labeled `lab-other-net`. That label is a key probe inside the
laboratory. It is not a second network confirmation.

## Evidence and limits

This laboratory adds experimental evidence for the proposed checks in
M1.6.1, M1.6.2, and M1.6.3, for the shared author procedure in M1.4.2,
and for the native-XEC clauses of M1.7.4, SEC-05, and S0-05. It does
not change their formal governance status. Where a row still requires
mainnet, regtest, a persisted indexer, or a production package,
laboratory evidence can be recorded as `PARTIAL`. `PARTIAL` does not
mean the unmet clause is met. `LAB_VALIDATED` is not used for these
rows. `LAB_VALIDATED` would not close the parent gate in any case.

Still required before those gates can be accepted: social version
activation, a persisted indexer, a real network reorg, a productive
tip profile, and settlement on an active chain. The frozen corpora,
the 127-row SEC-17 dispatch matrix, the 140-row S0 matrix, the three
D-07 samples, the ALP ancestry and replay suites, and the reaction
laboratory stay in place. No file under `packages/` is edited.
