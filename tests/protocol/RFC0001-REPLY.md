## Framing

`REPLY` is version `0x02`, event `0x02`.
The envelope layout is:
`version (1 byte) || event_type (1 byte) || author_input_index (1 byte) || parent_txid (32 bytes) || reply_text (1..180 bytes)`.
The envelope length budget is 36 to 215 bytes.

The script layout is:
`OP_RETURN (0x6a) + LOKAD push (0x04 0x54 0x4d 0x4d 0x00) + minimal envelope push + envelope`.
The script length budget is 43 to 223 bytes:
- An envelope <= 75 bytes uses direct push (`0x24..0x4b`), yielding scripts of 43 to 82 bytes.
  - Minimum script: 1 byte text -> 36-byte envelope, direct push `0x24` -> 43 bytes total.
  - Direct push boundary: 40 bytes text -> 75-byte envelope, direct push `0x4b` -> 82 bytes total.
- An envelope of 76 to 215 bytes uses `OP_PUSHDATA1` (`0x4c`), yielding scripts of 84 to 223 bytes.
  - PUSHDATA1 boundary: 41 bytes text -> 76-byte envelope, `0x4c 0x4c` -> 84 bytes total.
  - Maximum script: 180 bytes text -> 215-byte envelope, `0x4c 0xd7` -> 223 bytes total.

`parent_txid` is stored in 32 display-order bytes. It is not reversed and it
is not UTF-8 decoded. `reply_text` is decoded as strict UTF-8 (`TextDecoder`
with `{ fatal: true }`).
Encoder A (concatenation) and encoder B (explicit offsets) agree across all
valid configurations. The M1.3.8 sample (`illustrativeReplyScriptHex`) is 46 bytes.

A truncated envelope, a non-minimal push (e.g. `OP_PUSHDATA1` on <= 75 bytes),
empty text (0 bytes), text exceeding 180 bytes, and malformed UTF-8 (such as
byte `0xff`) are rejected by the laboratory decoder. Unknown version `0x09`
and unknown event `0x7e` are rejected.
The unmodified TM1 Core v1.0 parser returns `UNSUPPORTED_VERSION` for every
minimal social v2 script in this corpus, and `INVALID_FORMAT` for non-minimal framing.

## Authorship and parent linkage separation

M1.3.5 requires strict separation between transaction authorship and parent linkage:
- `authorship`: classified as `LAB_VALID` or `LAB_INVALID`. A valid signature
  unlocking the designated input prevout establishes authorship regardless of
  whether the parent transaction is known, pending, confirmed, or on another network.
- `parentLink`: classified as `PARENT_VERIFIED`, `PARENT_PENDING`, `INVALID_PARENT`,
  or `REFERENCE_CYCLE`.

Authorship positive rows cover Schnorr and ECDSA, sighash `0x41` and `0xc1`,
and author index 0, index 1, and index 2. The author input index may be any
valid in-range index. Input zero is not assumed to be the author.

Parent eligibility (M1.3.4):
- An active Core v1.0 POST is eligible and establishes `depth: 1` and `rootPostTxid: post.txid`.
- A verified social v2 REPLY is eligible as a parent for nested replies, establishing
  `depth: (parent.depth + 1)` and preserving `rootPostTxid: parent.rootPostTxid`.
- A transaction of kind `payment` or with an invalid parent signature yields `INVALID_PARENT`.
- An absent parent yields `PARENT_PENDING` with detail `ABSENT`. The reply's authorship
  remains `LAB_VALID`.
- A parent or reply from another network yields `INVALID_PARENT` with detail `OTHER_NETWORK`.
- Self-referencing or cyclic references yield `REFERENCE_CYCLE`.

`eligibleForThread` is true if and only if `structuralOk`, `authorship === "LAB_VALID"`,
and `parentLink === "PARENT_VERIFIED"`.

## Negatives

The corpus includes 19 negative scenarios:
1. `neg-signature-flipped`: scriptSig mutated -> `INVALID_AUTHOR_SIGNATURE`.
2. `neg-envelope-mutated`: OP_RETURN script mutated after signing -> `INVALID_AUTHOR_SIGNATURE`.
3. `neg-output-mutated`: change output mutated after signing -> `INVALID_AUTHOR_SIGNATURE`.
4. `neg-author-index-5`: envelope specifies input index 5 (out of range) -> `AUTHOR_INPUT_OUT_OF_RANGE`.
5. `neg-prevout-missing`: prevout metadata unavailable -> `PREVOUT_UNAVAILABLE`.
6. `neg-prevout-script`: prevout script altered -> `INVALID_AUTHOR_SIGNATURE`.
7. `neg-prevout-amount`: prevout amount altered -> `INVALID_AUTHOR_SIGNATURE`.
8. `neg-unsupported-script`: author input uses P2SH -> `UNSUPPORTED_AUTHOR_SCRIPT`.
9. `neg-parent-absent`: parent is not in catalog -> `PARENT_PENDING` (detail: `ABSENT`). Authorship is `LAB_VALID`.
10. `neg-parent-pending`: parent has invalid signature -> `INVALID_PARENT` (detail: `PARENT_AUTHOR_INVALID`).
11. `neg-parent-payment`: parent is plain payment -> `INVALID_PARENT` (detail: `INELIGIBLE_MESSAGE_TYPE`).
12. `neg-parent-other-network`: parent is on different network -> `INVALID_PARENT` (detail: `OTHER_NETWORK`).
13. `neg-reply-other-network`: reply evaluated on different network -> `INVALID_PARENT` (detail: `OTHER_NETWORK`).
14. `neg-nonminimal-push`: envelope <= 75 bytes uses `OP_PUSHDATA1` -> `INVALID_FORMAT`.
15. `neg-empty-text`: 0 bytes of text (35-byte envelope) -> `INVALID_FORMAT`.
16. `neg-text-too-long`: 181 bytes of text (216-byte envelope) -> `INVALID_FORMAT`.
17. `neg-malformed-utf8`: invalid UTF-8 byte sequence (`0xff`) -> `MALFORMED_UTF8`.
18. `neg-version-09`: unsupported version `0x09` -> `UNSUPPORTED_VERSION`.
19. `neg-event-7e`: unsupported event `0x7e` -> `UNSUPPORTED_EVENT`.

## Deterministic thread replay

In-memory replay (`applyReplyEvents` / `replayReplies`) enforces:
- Deduplication: replay is idempotent by transaction ID. Re-feeding the same txid
  leaves thread structure unchanged.
- Sibling ordering: siblings under the same parent/root are sorted deterministically
  by `(blockHeight, position, txid)`.
- Provisional mempool: unconfirmed mempool events are tracked in `provisional` and
  are not counted in `totalConfirmedCount` or added to confirmed threads.
- Withholding: events with structural errors, invalid authorship, or unverified
  parent linkage are withheld from thread emission.
