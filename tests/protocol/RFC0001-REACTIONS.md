## Framing

`REACTION` is version `0x02`, event `0x03`. `REACTION_REMOVE` is version
`0x02`, event `0x04`. `reaction_kind` `0x01` is LIKE. The envelope is
36 bytes: version, event, author index, 32-byte display-order
`target_txid`, and kind. The script is 43 bytes: `OP_RETURN`, a minimal
4-byte LOKAD push, and one minimal push of the envelope. Encoder A and
encoder B produce the same bytes. The decoder accepts only that shape.

A truncated envelope and a PUSHDATA1 envelope are rejected by the
laboratory decoder. Unknown version `0x09`, unknown event `0x7e`, and
unknown kind `0x7f` are rejected. The unmodified Core parser returns
`UNSUPPORTED_VERSION` for every minimal social script in this corpus,
including an unknown event, because it rejects the version before the
event byte. The nonminimal script fails Core as `INVALID_FORMAT`.
The eligible target remains a Core v1.0 POST and still parses.

`target_txid` is stored in display order. The decoder returns that hex.
It does not reverse the bytes and it does not treat them as UTF-8.

## Authorship and targets

Positive rows cover Schnorr and ECDSA, sighash `0x41` and `0xc1`, author
index 0, index 1, and index 2. The fee-paying input is not the author
when the designated index is nonzero. Each positive signature matches
the independent preimage and the declared P2PKH prevout.

Those prevouts are deterministic laboratory metadata from the canonical
fixture signer. `inputUnlockMatchesPrevout` checks the recorded script
and amount. They are not mainnet history and they are not Chronik
results.

Negative rows cover an altered signature, an envelope byte changed
after signing, author index 5 with one input, version `0x09`, kind
`0x7f`, event `0x7e`, and a nonminimal push. A missing target, a
payment target, and a POST whose own signature was altered are not
eligible. A reaction is withheld while its target is pending. That
reaction is not an active like.

## Replay

The state key is `(network, author_hash160, target_txid, reaction_kind)`.
The author hash is HASH160 of the designated input's pubkey. Confirmed
order is synthetic block height, position, then TXID.

On one synthetic sequence the same author does LIKE, a second LIKE, REMOVE,
a second REMOVE, and a later LIKE. The second LIKE stays in the history
and leaves the active count at one. The cold REMOVE starts at zero and
stays at zero. The second REMOVE stays at zero. The later LIKE becomes
the single active row for that key.

A second author can like the same post and can remove only that second
author's row. The removal does not clear the first author. A copy of a
removal retargeted at another network id does not clear the first
network. That copy is a key probe inside the state machine. It is not
a second confirmation of the same transaction.

Two synthetic branches share an ancestor. Branch A keeps both likes.
Branch B removes the first author, likes again, and then removes the
second author. The active count follows the selected branch. Events
that the selected branch has removed, and events that exist only on the
other branch, do not contribute to that count. Restoring the ancestor
checkpoint and applying branch B matches a from-scratch replay of
branch B. Applying branch B on top of branch A without that restore
does not. Reapplying a TXID that is already confirmed does not append
a second history row and does not change the count.

Confirmed order is recomputed across calls. An older event delivered
in a later batch is sorted with the events already stored, by block,
position, and TXID. It does not overwrite a newer event merely because
it arrived later.

Mempool rows are listed apart from confirmed rows. A mempool LIKE and a
mempool REMOVE do not change the confirmed count. When that same TXID
is later delivered as confirmed, it leaves the provisional list and
joins the confirmed order. A confirmed TXID sent again as mempool stays
out of the provisional list.

This selection is an in-memory laboratory. It is not a network
reorganization, not chain finality, and not a productive indexer.
Counts are a derived view, not consensus.
